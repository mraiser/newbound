The shelf

Every library is a stack of cards. No folders, no tree — a library holds assets and controls, a control holds everything else. Open a stack to fan out its controls.

plugin registrations — when TARGET is on a page, PLUGIN mounts at SELECTOR (runtime/dev/plugins.json via dev.plugins; changes apply on the next reload)

controls — dots show which facets each card carries

The library gate: comma-delimited security groups, written to meta.json as both the groups string and the enforced readers array (set_groups). Empty = admin-only. The convention for a library serving non-admin users is anonymous here, with fine-grained groups on individual controls and commands. Takes effect on restart.

The library's _ASSETS files, served at /app/asset/<lib>/<name>. Writes go through the agent API (write_asset/rename_asset/ delete_asset), journal-free but admin-gated.

Regenerates and recompiles this library's commands from the store (dev.dev.rebuild_lib) — the old dev UI's build button. Store edits (upserts, moves) can leave compiled code behind the records until a rebuild or restart; this is the deliberate catch-up act. Slow for big libraries; the instance keeps serving.


    

    

      
The library's versioned archive — the peer
      app-update path: publishing an app builds a signed zip of each of
      its libraries under runtime/dev/libraries, and peers in
      the update/admin groups install updates from
      exactly these. Git is development-only and plays no part here.
